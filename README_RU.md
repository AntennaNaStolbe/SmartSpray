## 📖 Описание
SmartSpray — проект по управлению мотором освежителя воздуха с платы **ESP8266**, интегрированный с **Home Assistant** через **MQTT**. Позволяет запускать распыление удалённо (из HA, веб-интерфейса или по таймеру/датчику движения).

## ⚙ Требования
- Плата **ESP8266 Wemos D1 Mini** (или совместимая)
- Драйвер мотора **TA6586** ([ссылка на Чип и Дип](https://www.chipdip.ru/product/ta6586-drayver-dvigatelya-iout-7a-dip-8-rz-9000663635))
- Автоматический освежитель **AirWick** ([ссылка](https://market.yandex.ru/product--air-wick-aerozol-dikii-granat-avtomaticheskii-so-smennym-ballonom-250-ml/1779356002?sku=439482020&uniqueId=8530975&do-waremd5=rUQvalKJ0Glrsh-DDBF9-Q&ogV=-3))
- **Home Assistant** с настроенным MQTT-брокером
- [PlatformIO](https://platformio.org/) (`pio` CLI) с поддержкой ESP8266
- Питание 5V. Возможно питание от батареек, но Wi-Fi потребляет много энергии, поэтому от батареек в простое заряд держится недолго

## 🔌 Подключение
- **DIG_PIN (D2)** — цифровой пин управления направлением мотора
- **PWM_PIN (D1)** — PWM-пин управления скоростью мотора
- Питание мотора — от внешнего источника (рекомендуется), с общим **GND** с ESP8266
- Для управления мотором используется драйвер **TA6586**

## 🔧 Настройка в коде
Логин/пароль WiFi и MQTT в коде **не хранятся** — они вводятся через веб-интерфейс при первом включении (см. ниже). В `include/config.h` настраиваются только несекретные параметры:

```cpp
// ====== DEVICE ID ======
// Технический ID устройства вычисляется автоматически из MAC-адреса ESP8266
// в рантайме — настраивать не нужно. Он стабилен и «зашит» в железо, поэтому
// MQTT-топики и сущности HA никогда не пересоздаются (даже после OTA/сброса).
// Дружелюбное имя (показывается в HA / веб-интерфейсе), настраивается через web.
#define DEVICE_NAME_DEFAULT  "SmartSpray"

// Версия прошивки — также тег релиза GitHub для авто-обновления ("v3.0.3")
#define FW_VERSION "3.0.3"

// Мощность (скорость) мотора. Подбирается опытным путём, т.к. у каждого
// освежителя свой механический люфт. По умолчанию (188) обычно работает.
const int MOTOR_POWER = 188;
```

Имя пользователя/пароль веб-интерфейса (опциональная защита) здесь **тоже** не задаются — они настраиваются при первичной настройке (см. ниже).

## 🚀 Первая прошивка (пошагово, для новичков)

### 1. Установите VS Code + PlatformIO
1. Установите [VS Code](https://code.visualstudio.com/).
2. В VS Code откройте панель **Extensions** и установите **PlatformIO IDE** (тот, что от "PlatformIO").
3. Откройте папку проекта (`SmartSpray`) — PlatformIO подхватит её автоматически.

> Если не хотите пользоваться VS Code, можно установить только [PlatformIO Core](https://platformio.org/install) (`pio` CLI).

### 2. (Опционально) Задайте дружелюбное имя устройства
Технический ID устройства генерируется автоматически из MAC-адреса чипа — настраивать для работы ничего не нужно (топики и сущности HA уникальны и стабильны из коробки, даже для многих устройств). Если хотите красивое имя в Home Assistant — задайте его на веб-странице настройки («Device name»). Чтобы изменить значение по умолчанию (если поле оставили пустым), правьте `DEVICE_NAME_DEFAULT` в `include/config.h`.

### 3. Подключите плату по USB
Подключите **Wemos D1 Mini** к компьютеру **данными**-кабелем (кабели только для зарядки не подойдут). Возможно, понадобится установить драйвер CH340 (на macOS/Windows он обычно уже есть).

### 4. Сборка и заливка
- **CLI:** выполните в папке проекта:
  ```
  pio run -e d1_mini -t upload
  ```
- **VS Code:** в панели PlatformIO появится окружение `d1_mini` — выберите его и нажмите кнопку **Upload** (→).

Прошивка скомпилируется и запишется на плату.

### 5. Следите за выводом (опционально)
- **CLI:**
  ```
  pio device monitor
  ```
- **VS Code:** PlatformIO → **Serial Monitor**.

После загрузки без конфига устройство запускает точку доступа **`SmartSpray Setup`** — можно переходить к первичной настройке ниже.

## 🛜 Первичная настройка (WiFi / MQTT / пароль веб-интерфейса)
При первом включении (или после сброса настроек) устройство запускает точку доступа **`SmartSpray Setup`**.

1. Подключитесь к этой Wi-Fi сети с телефона/компьютера (автоматически откроется captive portal; иначе откройте вручную `http://192.168.4.1`).
2. Заполните:
   - **Device name** (опционально) — дружелюбное имя, показываемое в Home Assistant. Предзаполнено `SmartSpray`; технический ID (используется в MQTT-топиках/HA) генерируется автоматически из MAC-адреса и вводить его не нужно.
   - **Wi-Fi сеть** — SSID и пароль вашей домашней сети
   - **MQTT-брокер** — адрес/порт брокера, логин и пароль (если требуются)
   - **Доступ к веб-интерфейсу** (опциональная защита) — отметьте «Требовать пароль для веб-интерфейса» и задайте логин/пароль (пароль от 4 символов). Не отмечайте — если пароль не нужен.
3. Нажмите **Save & Reboot** — устройство сохранит настройки в EEPROM, перезагрузится и подключится к вашей сети.

Настройки хранятся во флеше (EEPROM) и переживают перезагрузки **и** OTA-обновления.

> Если веб-защита включена, браузер запросит логин/пароль при открытии главной страницы устройства (HTTP Basic auth). Все управления (пшик, мощность, обновление, OTA, сброс) защищены.

## 🌐 Веб-интерфейс и OTA
После подключения к вашей Wi-Fi сети откройте в браузере `http://<ip-устройства>/` — доступна страница управления (сверху вниз):

- **Status** — WiFi ✓/✗ и MQTT ✓/✗ (обновляется раз в 5 сек)
- Кнопка **Spray 💦** — ручной пшик
- Слайдер **Spray force (мощность мотора)** — значение меняется вживую; подберите под свой освежитель (20–255, по умолчанию 188). Меняет мощность мотора и сохраняется в EEPROM (кнопкой **Save**)
- Кнопка **Check for updates** — ручная проверка GitHub (см. ниже)
- **Drag & drop зона** — прикрепите `.bin` файл для прошивки по воздуху (OTA)
- Кнопка **Update 💚** — серая по умолчанию, становится **зелёной**, когда **приложен файл** или **найдено обновление на GitHub**. По клику: если файл выбран — прошивает его по OTA; иначе, если есть обновление — ставит его с GitHub
- Окно **Logs** — последние отладочные сообщения устройства (кольцевой буфер на 40 строк), обновление раз в 3 сек, с кнопкой **Clear**
- Кнопка **Reset settings** — стереть настройки, перезагрузиться в режим точки доступа и вернуться к первичной настройке

### 👉 Как прошить по OTA (файл)
1. Соберите локально: `pio run` → файл `.pio/build/d1_mini/firmware.bin`
2. На странице устройства прикрепите его (drag & drop или через выбор файла)
3. Кнопка **Update** позеленеет — нажмите её и дождитесь перезагрузки устройства

> ⚠️ OTA-загрузка работает через `multipart/form-data` (веб-страница делает это автоматически). Отправка прошивки как «сырого» `application/octet-stream` (например, `curl --data-binary`) **не поддерживается** — устройство оборвёт соединение.

## 🔌 Поведение при недоступной сети (отключение света / загрузка роутера)

Устройство терпимо к временным сбоям сети и не требует перенастройки:

- **WiFi недоступен** (роутер грузится дольше устройства): устройство поднимает точку доступа **`SmartSpray Setup`** как **AP-страховку** и раз в 30 сек сканирует эфир в поисках настроенной сети. Как только ваша сеть появилась — подключается автоматически, AP гаснет и устройство возвращается в рабочий режим.
- Если WiFi/MQTT данные ввели неверно — подключитесь к AP-страховке `SmartSpray Setup`, исправьте настройки и нажмите **Save & Reboot**. Устройство не «зависает».
- **WiFi есть, но MQTT-брокер ещё грузится** (например, HA запускается 15 минут): устройство периодически пробует подключиться к MQTT (неблокирующе) и подключается, как только брокер готов. Веб-страница при этом остаётся доступной.

> Интервал проверки сети настраивается в `include/config.h` (`WIFI_RETRY_MS`).

## 🔄 Обновление с GitHub (проверка + ручная установка)

Устройство проверяет последний релиз `AntennaNaStolbe/SmartSpray` **раз в сутки**. Это только **проверка** — если вышла новая версия, оно предложит обновление, но **установка происходит только по явной команде** (кнопка **Update** на веб-странице или MQTT-команда `UPDATE`). Это защищает от «кирпича» из-за неудачной ночной авто-прошивки.

Также обновление можно проверить вручную кнопкой **Check for updates**.

### Как выпустить обновление
1. В `include/config.h` поднимите версию, например `#define FW_VERSION "3.1.0"`
2. Соберите: `pio run`
3. Создайте GitHub **Release** с тегом `v3.1.0` (= `FW_VERSION` с префиксом `v`)
4. Прикрепите к релизу ассет **`SmartSpray.bin`** — это файл `.pio/build/d1_mini/firmware.bin`

Устройства узнают о новой версии в течение суток (или по кнопке) и предложат её установить.

> ⚠️ Запросы к GitHub идут по HTTPS через `WiFiClientSecure.setInsecure()`. Канал шифрован, но сертификат не проверяется — приемлемо для домашнего OTA-сценария.

## 🏠 Интеграция с Home Assistant

Для автоматической регистрации устройства в HA используется MQTT Discovery. При подключении к MQTT устройство появляется в интеграции **MQTT** как устройство **SmartSpray** (или заданное дружелюбное имя) с сущностями:

- **Spraying** (button) — запустить пшик
- **Check updates** (button) — проверка обновлений на GitHub
- **Update** (button, появляется, только когда доступно обновление) — установить найденное обновление
- **Version** (sensor) — текущая версия прошивки
- **Update available** (binary sensor) — доступно ли обновление

Если устройство не появилось в HA автоматически, проверьте, что в интеграции MQTT включён "Enable device discovery".

### MQTT-топики
База для устройства **`<device_id>`** (`device_id` = MAC в нижнем регистре без двоеточий, стабильный): `antennans/SmartSpray/<device_id>/…`

| Топик | Назначение |
|-------|------------|
| `trigger` | Команды: `SPRAY`, `CHECK`, `UPDATE`, `STATUS` |
| `status` | JSON-статус (`version`, `update_available`, `online`) |
| `availability` | LWT online/offline |
| `version` | Retained, текущая версия (сенсор HA) |
| `update_available` | Retained, `true`/`false` (binary sensor HA) |

## 🤖 Идеи автоматизации для Home Assistant
После настройки освежителя на срабатывание от датчика движения или любого другого триггера рекомендуется:

1. Добавить helper **Counter** с минимумом 0 и максимумом 2700.
2. Добавить автоматизацию, инкрементирующую этот счётчик на +1.

Так можно отслеживать остаток баллона освежителя (в полном баллоне около 2700 «пшиков»).

Реализация такого счётчика в прошивке осознанно избегается:
1. Реальное число «пшиков» в баллоне может отличаться от 2700 — это примерное среднее. Проще подстроить в HA.
2. Сброс счётчика в 0 также проще делать из HA.
